# AGENTS.md — minikraken.com

Production SvelteKit 2 + Svelte 5 (runes) + TypeScript + Bun marketing site for MiniKraken IT.
Bilingual (base `nl`, secondary `en`), Node adapter, Tailwind 4 + DaisyUI, Paraglide i18n,
Elysia API, Valibot/Formisch forms, mdsvex blog.

## Repository map

- `src/routes/(web)/[[locale]]/` — localized pages (`about`, `process`, `realisations`,
  `contact`, `legal/*`, `blog/`). `[[locale]]` is optional; `nl` is base locale.
- `src/routes/(api)/api/[...slugs]/+server.ts` — Elysia app (`/api/healthz`, catch-all 404).
- `src/routes/(api)/sitemap.xml/+server.ts` — sitemap.
- `src/lib/components/base/` — primitives (`Button`, `Input`, `TextArea`, `Link`). Reuse before creating new ones.
- `src/lib/forms/` — **authoritative** Valibot schemas + logic (e.g. `contact.ts`). `src/lib/validators/` is currently empty — do not cite it.
- `src/lib/mailing/` — Resend delivery + templates. Never send real mail in tests.
- `src/lib/motion/`, `src/lib/stores/*.svelte.ts`, `src/lib/data/`, `src/lib/assets/` — animations, rune stores, site data, static assets.
- `src/lib/i18n/paraglide.inlang/` — editable Inlang project; `translations/**/*.json` are message sources. Generated `src/lib/i18n/paraglide/` is read-only.
- `tooling/vite-plugins/` — custom Vite plugins. `svelte.config.js` owns aliases + mdsvex; `vite.config.ts` owns Paraglide URL patterns + Vitest projects.
- Aliases (`svelte.config.js`): `$assets`, `$components`, `$data`, `$lib`, `$paraglide`, `$styles`, `$tooling`. Prefer them over deep relative imports.

## Commands (run from repo root)

- `bun install --frozen-lockfile` — install. `bun run dev` — dev server on `127.0.0.1:5173`.
- `bun run check` — full gate (`svelte-kit sync` + `format` + `lint` + `sv check`). Heavy; run narrow checks first during iteration. Lefthook `pre-commit` runs it.
- `bun run lint` — `prettier --check . && eslint .`. `bun run format` — `prettier --write .` (tabs, single quotes, no semicolons, width 100, Tailwind sorting via `src/lib/styles/base.css`).
- `bun run test` — all tests once. `bun run test:unit -- --run <path>` — focused run. Client tests are `*.svelte.{test,spec}.*` (browser/Chromium); server tests are `*.{test,spec}.*` (node). Note `vp` = `vite-plus` runner.
- `bun run build` — production build. `bun run preview` — preview Node build via `portless`.
- If a script isn't in `package.json`, don't invent it.

## Svelte 5 + SvelteKit conventions

- Svelte 5 runes only in new code: `$props()` (destructured + typed `Props`), `$state()`, `$derived()`, snippets + `{@render}`. No legacy `$:` reactive statements. Experimental `async` compiler flag is on — `svelte-code-writer` skill is authoritative for syntax.
- Components forward rest props (`{...rest}`); polymorphic primitives may use `<svelte:element>`. Keep `svelte/require-each-key` satisfied (keyed `{#each}`).
- SvelteKit experimental flags are on: `remoteFunctions`, `instrumentation.server`, `tracing.server`, `forkPreloads`. CSP `mode: 'auto'`.
- Server-only code (Resend clients, secrets, `sendEmail`) stays in server modules / `contact.remote.ts` command handlers — never importable from client components.
- Forms pattern (follow `contact` flow exactly): Valibot schema in `src/lib/forms/*.ts` → Formisch `createForm` + `Field` in `+page.svelte` → `command(Schema, handler)` in `*.remote.ts` re-checking honeypot/timing server-side with `invalid(...)` on failure.
- mdsvex `.md`/`.svx` blog posts REQUIRE frontmatter: `title`, `shortTitle`, `excerpt{en,nl}`, `date`, `updated`, `author`, `coverImage`, `categories`, `tags`, `draft` (enforced by `remark-lint-frontmatter-schema`).
- Styling: Tailwind 4 + DaisyUI utilities first; `prettier-plugin-tailwindcss` class order is enforced by formatter — don't hand-sort.
- i18n: `import { m } from '$paraglide/messages'` + `getLocale/localizeHref/setLocale` from `$paraglide/runtime`. Cookie `MINIKRAKEN_LOCALE`, strategy `cookie → preferredLanguage → url → baseLocale`. `src/hooks.ts` de-localizes URLs; `hooks.server.ts` runs `paraglideMiddleware`. Edit `translations/*.json`, never generated output. URL slugs are mapped in `vite.config.ts` (`/over-ons` ↔ `/en/about-us`, etc.) — preserve when adding routes.

## TypeScript

- `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, `verbatimModuleSyntax`, `isolatedModules`, `allowJs+checkJs`. Preserve — never loosen to silence an error.
- No `any`, no `@ts-ignore`/`@ts-expect-error`, no empty `catch {}`. Validate external input (FormData, params, API payloads) at the boundary with Valibot.
- `unicorn/filename-case` allows `camelCase|kebabCase|PascalCase`. Match surrounding file naming.

## Verification (required before handoff)

1. Narrowest check first (`sv check` on touched files / focused `test:unit`), then `bun run lint` for touched scope, then `bun run check` + `bun run test` + `bun run build` for anything touching routes, config, deps, or server boundaries.
2. Add/update tests for changed behavior (`src/lib/forms/contact.test.ts` is the pattern: normalization, honeypot, timing/expiry, FormData round-trip).
3. UI changes: verify in running browser at desktop + mobile widths. Never claim "verified" from static inspection alone.
4. Report commands run + anything skipped and why.
